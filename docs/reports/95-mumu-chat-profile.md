# MuMu Android 15 聊天性能排查报告

日期：2026-11-16。基线：`d8607a3`。状态：用户已确认提交，与任务96一并归档。

后续用户要求的高级效果、100条长消息及真实键盘压力测试见 `96-premium-long-chat-profile.md`；
该更重场景额外复现并定位了首次历史分页的完整状态日志开销，本报告的短消息结论不代替后续结果。

## 结论

本次没有复现聊天列表的持续掉帧。确定发现并修复的是 AI 消息预览的冗余重建：
同一滚动场景中 MessagePreview 构建从 **120 次降至 80 次（减少 33.3%）**。
视觉参数完全不变，明暗主题预览截图的逐像素比较通过。

这是一项缩小更新范围的优化，**不是“帧率提高 33%”**。正式采样 UI/raster
均远低于 60Hz 的 16.67ms 预算；当前数据没有证明整体帧耗时获得稳定改善。
没有据此继续削减玻璃、模糊、阴影或动画。

## 环境与方法

- 按用户提供的 MuMu ADB 教程核查端口，`MuMuManager.exe info -v all`
  确认 instance 0，连接 `127.0.0.1:16384`。
- Android 15 / API 35，x86_64，1080×1920，DPR 3，实际报告约 60Hz。
- Flutter 3.47.9 / Dart 3.13.7；`flutter build apk --profile` 生成 AOT profile APK，
  日志确认 **Impeller Vulkan**。不是 debug 模式的耗时，也不是 Widget 测试的运行耗时。
- 初始工作区干净；该模拟器未安装此包，因此建立专用的本地采样数据。
- 采样入口复用生产初始化、真实 ObjectBox、路由、聊天组件；240 条固定交替用户/AI
  消息，包含中文、英文、标题、列表、引用和行内代码。无真实模型或网页请求。
- 主对照：深色、标准玻璃、动画开启、AI 消息展开。4 次 0↔2400dp 往返滚动，
  每程 3 秒；先预热，再各取两轮正式样本。之后回装基线复测。
- `FrameTiming` 保存每帧 UI、raster、totalSpan 与 vsync 时间戳。每次录制前静置
  1.5 秒，结束后等待 1.2 秒，接收批量帧报告。
- 正式耗时样本关闭 Widget/layout/paint tracing；编译、测试期间的探索性采样不计入。
  调用次数另开详细追踪，每 2 秒保存 timeline 分段，按线程/时间戳/名称去重。

## 正式帧耗时

单位 ms；每列合并两次正式录制，各 2,898 帧。P90 表示 90% 的帧不超过该值。

| 指标 | 基线 A | 优化 B | 回装基线 A′ |
|---|---:|---:|---:|
| UI P50 | 0.387 | 0.482 | 0.439 |
| UI P90 | 0.732 | 0.847 | 0.822 |
| UI P99 | 1.366 | 1.499 | 1.479 |
| raster P50 | 2.710 | 2.628 | 2.698 |
| raster P90 | 4.042 | 3.922 | 4.013 |
| raster P99 | 5.966 | 6.061 | 6.195 |
| totalSpan P90 | 5.376 | 5.371 | 5.409 |
| UI 或 raster 超过 16.67ms | 0 / 2,898 | 0 / 2,898 | 0 / 2,898 |

UI 百分位略升、raster 中位/P90 略降、totalSpan P90 基本不变；方向并不一致，
不能选择单一指标宣称稳定加速。优化 B 两轮 UI P50 分别为 0.397 / 0.543ms，
也说明单次采样会波动。回装基线后 UI P90 从 0.732 变化至 0.822ms，进一步说明
环境波动的存在。totalSpan 含排队，不等于 UI+raster，不用于直接计算 FPS。

## 根因与修改

`MessagePreview` 原先使用 `useState<double>` 存储实测高度。首次布局、字体或子内容
高度变化时，只要数值变化就重新 build，即使消息仍完全放得下、显示状态完全相同。

现在使用 hook 托管的 `ValueNotifier<double>` 保存真实高度，选择器仅监听
`enabled && height > maximum`。高度仍准确保留；跨越阈值、改变视口或预留高度时，
展开提示、语义及命中行为仍随实际溢出状态更新。

| 同一详细追踪场景 | 基线 | 优化 |
|---|---:|---:|
| ChatTimelineMessageRow 构建 | 80 | 80 |
| MessageBubble 构建 | 80 | 80 |
| MessageTextContent 构建 | 80 | 80 |
| MessagePreview 构建 | 120 | 80 |
| MeasureSize Widget 构建 | 80 | 40 |
| RenderMeasureSize 追踪事件 | 82 | 82 |

减少的是不必要的 Widget 更新。底层真实测量仍保留，未把 Widget 构建减少误写成
布局或 GPU 工作减少。溢出的长消息仍允许必要的第二次更新。

## 其他观察与覆盖边界

- 标准档与高级档探索性滚动均未观察到持续超预算；正式 A/B 表只使用标准档。
- 无焦点静置 5 秒，基线和优化都记录到 **0 个新帧**，未发现该静态聊天场景持续刷帧。
- 连续草稿更新探索中曾记录 1 个 raster 长帧，详细追踪复测未重复出现；证据不足以
  归因于某个控件，不宣称已修复该偶发帧。
- MuMu 使用多个 Android 显示器。ADB 默认截图取到桌面，指定应用显示器的 Vulkan
  截图仍为黑色；原生 MuMu 窗口实际正常显示聊天和玻璃，因此未把黑图当渲染故障。
- 焦点开关脚本与草稿更新已运行；原生窗口未可靠显示完整软键盘，`mInputShown`
  也不能证明 Flutter 的 inset 动画。因此不把这些数据当作真实 IME 入退场的性能验收。
  键盘布局、避让和中途切换由既有 Widget 测试回归覆盖。
- 未测实际联网 AI 流式响应、超长 Markdown/大图混排压力、手机热降频和 120Hz。
  模拟器 GPU/显示链路不同于实体 Android/iOS，结论仅适用于本次同环境对照。
