# 高级效果 / 100 条长消息性能复测

2026-11-16；沿用任务95的预览优化，本次进一步定位分页长帧。用户已确认提交。

## 测试条件

- MuMu Android 15、1080×1920、DPR 3、60Hz；Flutter profile AOT、Impeller Vulkan。
- 高级渲染、动画开启、深色、AI 讨论展开。高级档仍遵守项目预算：顶部/悬浮按钮
  可 premium，输入框/Tab 共用背景最高 standard，不强制把所有控件都改为 premium。
- 数据恰好100条：50条用户消息、50条AI Markdown。每条AI含16个同构章节，包含
  中英文、标题、列表、引用及行内代码。实测挂载正文均为6875dp，约10.7个640dp屏幕，
  高于“至少两屏”要求。列表仍保留生产半屏预览与展开入口；正文布局确实存在于预览下面。
- 慢速滚动每段2400dp/3秒，10段遍历历史，最后4秒回底；快速为2400dp/1秒。
  目标按当时最大滚动范围限幅，实际触发50→100和100→150的历史窗口请求。
  后一个请求用于确认无更多数据，数据库仍只有100条，不是插入了150条。
- 首次遍历与预热后重复遍历分开；正式统计关闭详细 tracing，且没有并行构建/测试/录屏。
  初次探索时混入分析任务的样本不用于归因，另行重启并隔离复现。

## 滚动结果与新发现

原实现（包含任务95预览优化）预热后很平稳，但首次分页会卡顿：

| 场景 | 帧数 | UI P99 / 最大 ms | raster P99 / 最大 ms | UI或raster超16.67ms |
|---|---:|---:|---:|---:|
| 慢速，预热后两轮 | 4104 | 4.357 / 9.722 | 6.569 / 9.286 | 0 |
| 快速，预热后两轮 | 1704 | 5.161 / 7.921 | 6.317 / 8.729 | 0 |
| 首次遍历，隔离复测 | 2046 | 4.803 / 54.620 | 5.489 / 8.255 | 3 |
| 恢复console的冷遍历对照 | 2046 | 4.910 / 55.378 | 5.802 / 8.693 | 3 |
| 同包仅临时关闭console | 2052 | 4.612 / 11.707 | 5.660 / 11.083 | 0 |
| 修复后首次遍历，console开启，第1轮 | 2052 | 4.807 / 7.569 | 5.358 / 8.176 | 0 |
| 修复后再次重启首次遍历，第2轮 | 2052 | 4.737 / 8.119 | 5.693 / 8.578 | 0 |
| 修复后快速滚动 | 852 | 4.915 / 9.547 | 5.932 / 8.437 | 0 |

隔离复测的三个 UI 长帧为19.929、28.021、54.620ms，发生在约13.58/13.62/26.93秒。
它们与历史窗口扩大附近相符。raster没有同步变慢，不能把这些卡顿直接归咎于高级玻璃。

CPU诊断样本在对应区间出现 `TalkerRiverpodObserver.didUpdateProvider`、
`Talker._handleLogData`、`TalkerLogger.log`、`ExtendedLoggerFormatter.fmt`，以及
Riverpod调度/Widget重建。结合console关闭消失、开启重现，支持完整状态日志是显著诱因；
追踪有额外开销，不用诊断样本的耗时替代正式结果，也不声称它是唯一成本。

## 键盘与 Tab 动画

用户确认原 MuMu 点击输入框看不到软键盘。检查发现预装“搜狗”实际位于
`/system/priv-app/nemu-vinput-pack`：输入法标记可见，但实际窗口高度为0。
因此上次焦点测试不能代表此次要求的真实键盘动画。

本次构建了独立、无网络权限、不记录输入的280dp Android测试键盘。它通过原生
`InputMethodService` 打开系统IME窗口，没有向Flutter注入假MediaQuery。MuMu把IME放在
display0，因此将当前应用task也移到display0；已经截图、录像和数据三重核验。

- 正式两轮共16次开合，所有打开端点：inset=280dp、Tab高度=0、keyboardOpen=true。
- 所有关闭端点：inset=0、Tab高度=60dp、keyboardOpen=false。
- 捕获过渡态：inset=188.67dp、Tab高度=45.56dp，说明确实执行中间动画。
- 原日志配置下1452帧：UI P99 **3.925ms**，raster P99 **9.178ms**，最大分别5.310/11.978ms。
- UI/raster均未超16.67ms；totalSpan有2帧超过预算，最大16.973ms。totalSpan含排队，
  不能据此断言“完全零显示延迟”。键盘动画合成成本高于静态列表滑动，但没有持续卡顿证据。
- 这是测试IME触发的系统开合与应用Tab动画，不代表搜狗/Gboard候选词、联想或输入算法性能。

## 修复与验证

本次生产修改为 `lib/main.dart` 的 `printStateFullData: false`。
保留Provider事件、类型摘要、控制台输出及错误详情/堆栈，避免分页时串行打印整批长正文。
调试权衡是 previous/new 状态不再展开完整值；需要时应单独记录有界业务摘要。
没有改变玻璃、模糊、动效、列表布局或预览高度。

新增 `test/main_test.dart` 三项契约：状态toString不被调用、100条长消息分页日志有界、
失败详情及堆栈保留。前两项先失败，修改后全部通过；相关12项通过。
全量 **867项通过**，`flutter analyze --no-pub` **零问题**。格式与diff检查通过。
最终包保持console开启，首次遍历第一轮已验证UI最大7.569ms、0个UI/raster长帧。
再次重启后的第二轮UI最大8.119ms，同样0个超预算帧；两次冷遍历共4104帧。
修复前后P99变化不大，收益主要是移除了分页时约55ms的尾部尖峰，不能宣称每一帧都加速。

最终包键盘三轮共24次开合、2181帧，48个开/关端点都满足真实inset与Tab高度契约：

| 键盘复测 | UI P99 / 最大 ms | raster P99 / 最大 ms | 超预算帧 |
|---|---:|---:|---:|
| 首轮及后续两轮合计 | 4.140 / 6.539 | 9.882 / 22.679 | 2 / 2181 |
| 后续两轮（16次开合） | 4.098 / 5.108 | 9.515 / 12.317 | 0 / 1454 |

两个raster长帧均出现在最终包第一轮，分别22.679ms和17.868ms；三轮totalSpan最大
29.771ms。后两轮totalSpan最大16.121ms。保留首轮而非只报告预热结果：可以说持续
开合总体平稳，但仍有少量首轮合成尖峰，未证明彻底消除所有抖动。它们不应归入已修复的
分页日志问题，也没有通过降低玻璃质量掩盖。本轮没有为两个偶发GPU帧扩大UI改动。
